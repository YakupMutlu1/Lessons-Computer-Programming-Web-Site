Gömülü Sistemlere Giriş ve Temel Kavramlar (Hafta 1–2)

Gömülü Sistem Nedir?

Gömülü sistem (embedded system), belirli bir görevi yerine getirmek için tasarlanmış, genellikle kullanıcı fark etmeden çalışan bilgisayar sistemidir. Masaüstü PC gibi genel amaçlı değildir; örneğin çamaşır makinesi kontrol kartı, araç ABS ünitesi, akıllı termostat veya NodeMCU tabanlı sıcaklık istasyonu gömülü sistem örneğidir.

Bu sistemlerde yazılım (firmware) donanıma sıkı bağlıdır; güncelleme nadiren OTA (over-the-air) veya USB ile yapılır. Donanım maliyeti, güç tüketimi ve fiziksel boyut genelde önceliklidir.

  • Girdi: sensörler, düğmeler, haberleşme hatları
  • İşleme: MCU/MPU üzerinde çalışan program
  • Çıktı: motor, röle, ekran, ağ üzerinden veri
Sınavda sorulabilirGömülü sistem = belirli görev + gömülü yazılım + kısıtlı kaynaklar. Genel amaçlı PC tanımı yanlıştır.

Mikrodenetleyici (MCU) ve Mikroişlemci (MPU)

MCU (Microcontroller): CPU, RAM, Flash program belleği, zamanlayıcılar, ADC, UART/SPI/I2C gibi çevre birimleri tek entegrede toplanır. Arduino Uno (ATmega328P), ESP8266, STM32 gömülü projelerde yaygındır.

MPU (Microprocessor): Odak CPU’dur; bellek ve çevre birimleri genelde harici çiptir. Raspberry Pi, telefon işlemcileri MPU ailesine yakındır; işletim sistemi ve daha yüksek kaynak tüketimi beklenir.

Firmware Kavramı

Firmware, cihazın Flash belleğine yazılan ve güç kesilse bile kalan programdır. İşletim sistemi kurulumu gibi kullanıcı tarafından sık değiştirilmez; bootloader üzerinden yeni sürüm yüklenir.

Arduino IDE’de derlediğiniz .ino dosyası, derleme sonrası makine koduna dönüşür ve kartınıza upload ile firmware olarak yazılır. ESP8266’da ayrıca WiFi stack ve AT firmware varyantları vardır; derslerde genelde Arduino core kullanılır.

// setup() ve loop() — tipik Arduino firmware yapısı
void setup() {
  Serial.begin(115200);
  Serial.println("Firmware basladi");
}
void loop() {
  // Ana görev dongusu
}
DikkatFirmware güncellemesi yarım kalırsa cihaz açılmayabilir; yükleme sırasında kabloyu çıkarmayın ve doğru kart/port seçin.

Gömülü Sistem Kısıtları

Tasarım kararları aşağıdaki sınırlar içinde verilir:

  1. Gerçek zamanlılık: Bazı olaylar belirli süre içinde yanıtlanmalıdır (ör. motor frenleme, alarm).
  2. Bellek: ESP8266’da KB–MB düzeyi RAM; büyük buffer’lar heap taşmasına yol açar.
  3. Güç: Pil ile çalışan cihazlarda mA altı tüketim hedeflenir.
  4. Maliyet ve boyut: Tek katmanlı PCB, az bileşen.
  5. Güvenilirlik: Sıcaklık, EMI, watchdog ile kilitlenmeye karşı koruma.

4K oyun grafikleri veya sınırsız bulut depolama gömülü kısıt listesine girmez; bu tür işler MPU + OS tarafına kayar.

Sınavda sorulabilirKritik kısıtlar: gerçek zamanlılık, düşük güç, sınırlı bellek — “yüksek çözünürlüklü oyun” değil.

Harvard ve Von Neumann Mimarisi

Von Neumann: Program ve veri aynı bellek yolunu paylaşır; modern PC’ler buna yakındır.

Harvard: Program belleği (Flash) ile veri belleği (RAM) için ayrı veri yolları; birçok MCU aynı anda komut fetch ve veri erişimini hızlandırır.

Harvard (özet) CPU ----> Program Bus ----> Flash (kod) CPU ----> Data Bus ----> RAM (değişkenler, yığın)

Arduino’da kod Flash’ta, değişkenler RAM’de tutulur; bu ayrım Harvard fikrine uygundur, fakat çevre birimleri ve önbellek detayları çipe göre değişir.

Sınavda sorulabilirHarvard = program ve veri yolu ayrılabilir. Von Neumann = tek bellek alanı paylaşımı.

NodeMCU ve IoT (ESP8266)

ESP8266 ve NodeMCU Kartı

ESP8266, WiFi yetenekli, düşük maliyetli bir MCU çözümüdür. NodeMCU modülü, ESP8266’yı breadboard dostu pinler, USB–serial dönüştürücü ve 3.3V regülatör ile taşır.

  • İşlemci: Tensilica L106, 80/160 MHz
  • WiFi: 802.11 b/g/n, istasyon (STA) ve erişim noktası (AP) modları
  • GPIO: D0–D8 (kart etiketleri); bazı pinler boot sırasında özel davranır
DikkatD0 (GPIO16) boot modunu etkileyebilir; projede strapping pin kurallarını okuyun.

3.3V Mantık Seviyesi

ESP8266 pinleri 3.3V tolerant değildir; 5V Arduino çıkışını doğrudan bağlamak çipi bozabilir. 5V sensörler için seviye çevirici (level shifter) veya direnç bölmeci gerekir.

// NodeMCU pin etiketi vs GPIO (örnek — board.txt'e gore dogrulayin)
// D1 -> GPIO5, D2 -> GPIO4, D5 -> GPIO14 ...
#define LED_PIN D4  // veya 2 (GPIO2) — kart semasina bakin
SeviyeTipik HIGHNodeMCU uyumu
3.3V TTL~3.3VUyumlu
5V TTL~5VRiskli — çevirici kullan

WiFi ve IoT Bağlantısı

ESP8266, ev ağına bağlanarak sensör verisini HTTP/MQTT ile sunucuya gönderebilir. IoT katmanında cihaz istemci, bulut veya yerel broker sunucu rolündedir.

#include <ESP8266WiFi.h>

const char* ssid = "AgAdi";
const char* pass = "Sifre";

void setup() {
  Serial.begin(115200);
  WiFi.mode(WIFI_STA);
  WiFi.begin(ssid, pass);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println(WiFi.localIP());
}
İpucuWiFi bağlantısı güç çeker; pil projelerinde bağlantıyı gerektiğinde kurup sonra deep sleep düşünün.

Arduino IDE Kurulum ve Kart Seçimi

  1. Arduino IDE → Dosya → Tercihler → Ek Kart Yöneticisi URL: http://arduino.esp8266.com/stable/package_esp8266com_index.json
  2. Araçlar → Kart → Kart Yöneticisi → “esp8266” yükle
  3. Kart: NodeMCU 1.0 (ESP-12E Module), doğru COM port

Yanlış kart seçimi pin eşlemesini ve flash boyutunu bozar; upload hatası veya sürekli reset görülebilir.

Sınavda sorulabilirNodeMCU = ESP8266 tabanlı. Mantık seviyesi 3.3V. Program yükleme USB–UART üzerinden.

İlk Proje: Blink (LED Yak–Söndür)

Donanımı doğrulamanın en kısa yolu dahili veya harici LED’i yakıp söndürmektir. NodeMCU’da genelde D4 (GPIO2) üzerinde dahili LED vardır.

void setup() {
  pinMode(LED_BUILTIN, OUTPUT);
}
void loop() {
  digitalWrite(LED_BUILTIN, LOW);   // Bazı kartlarda LOW = yanik
  delay(500);
  digitalWrite(LED_BUILTIN, HIGH);
  delay(500);
}
İpucuLED yanmıyorsa pin tanımını ters deneyin veya harici LED + 220Ω direnç ile 3.3V–GND arası bağlayın.

Devre Prototipleme

Breadboard (Ekmek Tahtası) Kullanımı

Breadboard, lehim gerektirmeden devre kurmanızı sağlar. Orta bölgede aynı satırdaki 5 delik elektriksel olarak kısa devredir; ortadaki kanal iki yarıyı ayırır. Kenar power rail (+ / −) genelde uzun şerit halinde bağlıdır.

  • MCU GND ile breadboard mavi hatta, 3.3V/5V kırmızı hatta ortaklanmalı
  • Uzun bacaklı entegreler kanalın iki yanına oturtulur
  • 20 MHz üzeri RF devrelerde breadboard gürültüsü artar; IoT dersleri için yeterlidir

LED ve Direnç Hesabı (Ohm Yasası)

LED, polariteli bir diyottur; ters bağlanırsa yanmaz. İleri yönde tipik düşüm VLED ≈ 2V (kırmızı). Akımı sınırlamak için seri direnç şarttır.

Formül: R = (Vkaynak − VLED) / I

Örnek: 3.3V kaynak, 2V LED, hedef 10 mA → R = (3.3 − 2) / 0.01 ≈ 130Ω → standart 220Ω güvenli seçimdir.

// Kabaca hesap — 330 ohm cogu 3.3V LED icin uygundur
#define LED_PIN 5
void setup() {
  pinMode(LED_PIN, OUTPUT);
}
DikkatDirencsiz LED deneyi çip pininden çok akım çeker; pin ve LED zarar görür.

Pull-up ve Pull-down Dirençleri

MCU girişi bağlı değilken floating kalır; okuma rastgele 0/1 verir. Pull-up: pin boştayken HIGH’a çeker (düğmeye basınca GND ile LOW). Pull-down: boştayken LOW.

// Dahili pull-up — harici direnc gerekmeyebilir
pinMode(BUTTON_PIN, INPUT_PULLUP);
int okunan = digitalRead(BUTTON_PIN);
// INPUT_PULLUP: basili degilken HIGH, basinca LOW (GND'ye cekilir)

Harici pull-up değeri genelde 4.7kΩ–10kΩ; I2C hatlarında 4.7kΩ tipiktir.

Sınavda sorulabilirPull-up amacı: floating pini tanımlı lojik seviyede tutmak.

Kapasitör, Diyot, Transistör

Kapasitör

Decoupling (100nF): MCU VCC–GND arasına yakın yerleştirilir; ani akım çekiminde voltajı stabilize eder, gürültüyü filtreler.

Diyot

Röle bobini üzerine flyback diyot (ör. 1N4007) ters polariteyle bağlanır; kapanırken oluşan ters EMK’yı söndürür, transistörü korur.

Transistör (NPN, örn. 2N2222)

MCU pin akımı (~12–20 mA) röle bobinini sürmek için yetersizdir; transistör anahtar görevi görür.

Dijital ve Analog Giriş–Çıkış (GPIO)

pinMode: INPUT, OUTPUT, INPUT_PULLUP

Her GPIO pini yazılımda yön tanımlanmalıdır. setup() içinde bir kez yapılması yeterlidir.

#define PIN_LED 4
#define PIN_BTN 0

void setup() {
  pinMode(PIN_LED, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
}
ModAnlam
OUTPUTPin sürer (LED, röle tetik)
INPUTOkuma; harici pull gerekebilir
INPUT_PULLUPDahili direnç ile varsayılan HIGH

digitalRead ve digitalWrite

Dijital değerler LOW (0) ve HIGH (1)’dir. digitalWrite(pin, HIGH) çıkışı lojik 1 yapar; röle modülünde tetik mantığı ters olabilir (active-low).

void loop() {
  if (digitalRead(PIN_BTN) == LOW) {
    digitalWrite(PIN_LED, HIGH);
  } else {
    digitalWrite(PIN_LED, LOW);
  }
}
İpucuButon debounce için yazılımda 20–50 ms gecikme veya millis() ile kenar algılama kullanın.

analogRead ve ADC

Arduino Uno’da ADC 10 bit (0–1023) çözünürlük verir; referans genelde 5V (kartına göre 3.3V). NodeMCU’da tek ADC pini (A0) vardır.

int ham = analogRead(A0);
float voltaj = ham * (3.3 / 1023.0);  // ESP8266 A0 icin ornek olcek
Serial.println(voltaj);

LDR veya potansiyometre ile voltaj bölücü kurulur; analog değer ortam ışığına göre değişir.

Sınavda sorulabilirUno analogRead: 10 bit → 0–1023. INPUT_PULLUP boşta HIGH sağlar.

PWM (analogWrite)

PWM hızlı aç–kapa ile ortalama voltajı ayarlar; LED parlaklığı, DC motor hızı, servo açısı (1–2 ms darbe) için kullanılır. ESP8266’da analogWrite frekansı sınırlıdır; servo için ESP8266Servo kütüphanesi tercih edilir.

// LED parlakligi — 0-1023 (ESP) veya 0-255 (Uno PWM)
analogWrite(LED_PIN, 512);

Servo sinyali genelde 50 Hz, darbe genişliği 1000–2000 µs aralığında açıyı belirler.

UART, SPI, I2C ve MQTT

UART (Seri Haberleşme)

UART asenkron, noktadan noktaya iletişimdir. Minimum iki hat: TX (gönder), RX (al). Baud rate saniyedeki sembol hızıdır (ör. 115200).

void setup() {
  Serial.begin(115200);  // USB-UART uzerinden PC ile
}
void loop() {
  if (Serial.available()) {
    char c = Serial.read();
    Serial.print("Gelen: ");
    Serial.println(c);
  }
}

NodeMCU program yükleme ve debug aynı UART üzerinden yapılır; ek modül ile GPS (NEMA cümleleri) bağlanabilir.

ParametreÖrnek
Baud9600, 115200
Veri bit8
EşlikNone (N)

SPI (Serial Peripheral Interface)

SPI senkron, yüksek hızlı; birden fazla slave için CS (Chip Select) hatları kullanılır.

  • MOSI: Master Out Slave In
  • MISO: Master In Slave Out
  • SCK: Saat
  • CS/SS: Hangi cihazın seçili olduğu
#include <SPI.h>
// SD kart veya NRF24 — CS pinine gore slave secilir
digitalWrite(CS_PIN, LOW);   // Slave aktif (cipe gore)
SPI.transfer(0xFF);          // Bir byte veri
digitalWrite(CS_PIN, HIGH);
Sınavda sorulabilirSPI hatları: MOSI, MISO, SCK, CS. UART: TX, RX.

I2C (I²C, TWI)

İki hat: SDA (veri), SCL (saat). Her slave’nin 7-bit adresi vardır; aynı hatta birden fazla cihaz (adres çakışmaması şartıyla).

Arduino Uno: SDA = A4, SCL = A5. NodeMCU: D1 (GPIO5) SCL, D2 (GPIO4) SDA tipik.

#include <Wire.h>
#define I2C_ADDR 0x3C  // OLED ornek

void setup() {
  Wire.begin();
  Wire.beginTransmission(I2C_ADDR);
  Wire.write(0x00);
  Wire.endTransmission();
}

Pull-up dirençleri (4.7kΩ) SDA ve SCL üzerinde gereklidir; bazı modüllerde hazır gelir.

MQTT hafif yayınla–abone ol (publish/subscribe) protokolüdür. Broker (ör. Mosquitto, HiveMQ) mesajları topic adlarına göre yönlendirir.

Sensörler ve Aktüatörler

DHT11 / DHT22 Sıcaklık ve Nem

DHT tek hat üzerinden dijital protokolle sıcaklık ve nem gönderir. Zamanlama kritiktir; hazır kütüphane kullanmak pratiktir.

#include <DHT.h>
#define DHT_PIN 14
#define DHT_TYPE DHT11
DHT dht(DHT_PIN, DHT_TYPE);

void setup() {
  Serial.begin(115200);
  dht.begin();
}
void loop() {
  float t = dht.readTemperature();
  float h = dht.readHumidity();
  if (isnan(t)) Serial.println("DHT okuma hatasi!");
  else Serial.printf("T=%.1f H=%.1f\n", t, h);
  delay(2000);
}
DikkatDHT okumaları arasında en az 1–2 saniye bekleyin; çok sık okuma hatalı sonuç verir.

PIR Hareket ve HC-SR04 Mesafe

PIR

Pasif kızılötesi hareket algılar; çıkış dijital HIGH/LOW verir. Alarm ve otomatik lamba projelerinde kullanılır.

pinMode(PIR_PIN, INPUT);
if (digitalRead(PIR_PIN) == HIGH)
  Serial.println("Hareket algilandi");

HC-SR04 ultrasonik

Trig’e kısa pulse, Echo süresinden mesafe: d = (süre × ses hızı) / 2. Ses hızı ~343 m/s.

digitalWrite(TRIG, HIGH);
delayMicroseconds(10);
digitalWrite(TRIG, LOW);
long sure = pulseIn(ECHO, HIGH);
float cm = sure * 0.034 / 2;

LDR (Işık Bağımlı Direnç)

LDR direnci ışık arttıkça düşer. Voltaj bölücü ile analog pine bağlanır; gece gündüz algılama ve otomatik aydınlatma için uygundur.

int isik = analogRead(A0);
if (isik < 300) digitalWrite(LAMP_PIN, HIGH);
else digitalWrite(LAMP_PIN, LOW);

Bellek Yönetimi

Flash ve RAM

Flash: Program kodu ve sabit veriler (PROGMEM). Güç kesilince kalır. ESP8266’da genelde 4 MB dış flash (karttan karta değişir).

RAM: Çalışma zamanı değişkenleri, heap, stack. Güç kesilince silinir. String birleştirme ve büyük buffer’lar RAM’i hızla doldurur.

// ESP8266 heap kontrolu
Serial.printf("Free heap: %u\n", ESP.getFreeHeap());
DikkatString sınıfı parça parça büyüyerek heap fragmantasyonu yapabilir; char[] veya snprintf tercih edin.

EEPROM

EEPROM byte düzeyinde silinebilir/yazılabilir kalıcı alandır; WiFi ayarı, kalibrasyon, sayaç saklamak için kullanılır. Yazma döngüsü sınırlıdır (yüz binler–milyonlar); sık yazılan log için uygun değildir.

#include <EEPROM.h>
void setup() {
  EEPROM.begin(512);
  int sayac = EEPROM.read(0);
  sayac++;
  EEPROM.write(0, sayac % 256);
  EEPROM.commit();  // ESP8266'da commit gerekir
}

Flash ile fark: EEPROM daha çok küçük parametre güncellemesi; Flash tam program imajı içindir.

Stack ve Heap

Stack: Fonksiyon çağrıları, yerel değişkenler; LIFO. Derin özyineleme veya büyük yerel dizi stack taşmasına (crash) yol açar.

Heap: malloc, new, String için dinamik alan. Serbest bırakılmazsa sızıntı olur.

Bellek ozeti (ESP8266) Flash -> sketch + OTA partition RAM -> stack (asagi) + heap (yukari) + static
Sınavda sorulabilirStack = fonksiyon/yerel. Flash = program kodu. Heap = dinamik ayırma.

Gömülü İşletim Sistemleri ve Gerçek Zamanlılık

FreeRTOS ve Görev (Task) Kavramı

RTOS, çoklu görevi zaman dilimleriyle yönetir. ESP8266 Arduino core’da arka planda FreeRTOS benzeri scheduler çalışır; ESP32’de açıkça task oluşturmak yaygındır.

// ESP32 ornek — xTaskCreate
void gorevA(void* p) {
  for (;;) {
    Serial.println("A");
    vTaskDelay(500 / portTICK_PERIOD_MS);
  }
}
void setup() {
  xTaskCreate(gorevA, "A", 2048, NULL, 1, NULL);
}

Deadline: Görevin mutlaka tamamlanması gereken son süre. Kaçırılırsa sistem güvenliği bozulabilir (ör. airbag).

Mutex ve Semaphore

Mutex: Paylaşılan kaynağa (I2C bus, SD dosyası) aynı anda tek task erişsin diye kilit. Semaphore: Sayısal sayaç; üretici–tüketici kuyruklarında kullanılır.

Mutex alındıktan sonra mutlaka serbest bırakılmalı; aksi halde diğer görevler sonsuza dek bekler (deadlock).

İpucuArduino loop() tek görev gibi görünür; WiFi stack arka planda çalışırken uzun delay yerine yield() veya non-blocking kod yazın.

Kesme Servis Rutini (ISR)

Donanım olayı (pin kenarı, timer) olduğunda CPU ana akışı durur, ISR çalışır. ISR kısa olmalı: bayrak koy, asıl işi loop veya task’ta yap.

volatile bool tetik = false;
void IRAM_ATTR onKenar() {
  tetik = true;
}
void setup() {
  attachInterrupt(digitalPinToInterrupt(4), onKenar, RISING);
}
DikkatISR içinde delay(), Serial.print veya mutex kullanmayın.

Bare-metal vs RTOS

Bare-metal

Süper döngü + interrupt; minimal bellek, tam kontrol. Küçük LED projeleri.

RTOS

Çoklu görev, öncelik, senkronizasyon. Karmaşık IoT, motor kontrol.

Linux çalışan Raspberry Pi “gömülü” sınırında sayılır; ders NodeMCU hattında bare-metal’a yakın Arduino + isteğe bağlı RTOS kavramları işlenir.

Güç Yönetimi

Sleep Modları (Deep / Light)

ESP8266 deep sleep ile µA seviyesine iner; uyandırmak için RST veya timer gerekir. Light sleep WiFi bağlantısını daha hızlı geri getirir ama daha çok tüketir.

// Deep sleep 30 saniye — ESP8266
// ESP.deepSleep(30e6);  // mikrosaniye
// Uyaninca setup() bastan calisir

Polling yerine interrupt ile uyumak düşük güç tasarımının temelidir.

Watchdog Timer (WDT)

Yazılım kilitlenirse WDT süresi dolunca MCU’yu resetler. ESP8266’da ESP.wdtFeed() veya düzenli yield() beklenir.

Brown-out reset: Besleme voltajı kritik altına düşünce güvenli reset; flash yazımı sırasında önemlidir.

Sınavda sorulabilirWDT amacı: kilitlenmede otomatik reset. Deep sleep amacı: güç tasarrufu.

Pil Besleme ve Düşük Güç Tasarımı

  • LiPo + şarj modülü + 3.3V regülatör (AMS1117) yaygın kombinasyon
  • Her pin OUTPUT HIGH/LOW tutmak gereksiz akım çeker; kullanılmayan pin INPUT veya uygun mod
  • WiFi’yi sadece veri gönderirken aç; MQTT keep-alive süresini optimize et
DikkatUSB ve pil aynı anda bazı kartlarda çakışma yapar; şema okuyun.

Hata Ayıklama (Debugging)

Serial Monitor ile Yazılım Debug

En erişilebilir yöntem: Serial.print ile değişken, durum makinesi ve hata kodlarını izlemek. Baud IDE ile eşleşmeli.

#define DEBUG 1
#if DEBUG
  #define LOG(x) Serial.println(x)
#else
  #define LOG(x)
#endif

void loop() {
  LOG("Sensör okunuyor...");
}
İpucuÇok sık print WiFi zamanlamasını bozabilir; kritik döngüde seyrek loglayın.

Logic Analyzer ve Osiloskop

Logic analyzer: Dijital hatların zamanlamasını yakalar; I2C/SPI decode ile paket görülür. Saat hızı cihaz limitine bağlıdır.

Osiloskop: Analog dalga formu (PWM, gürültü, UART seviyesi). Rise time ve voltaj doğrulanır.

Floating Pin ve Gürültü

Bağlanmamış giriş rastgele değer okur; buton “hayalet basma” yapar. Çözüm: pull-up/down, kısa kablo, decoupling kapasitör, motor/röle yakınında opto izolasyon.

Dönem Projesi

Proje Gereksinimleri

Tipik dönem projesi en az bir sensör, bir aktüatör veya uzaktan kontrol, haberleşme (Serial/WiFi/MQTT) ve dokümantasyon ister.

  4. Test sonuçları ve sınırlamalar
Sınavda sorulabilirProje sunumunda: problem, çözüm, canlı demo, sonuç — sadece kod kopyası yeterli değildir.

Prototip aşaması: Breadboard’da parça parça doğrulama (LED → sensör → WiFi → MQTT). Her adımda çalışan ara sürüm tutun.

Rapor bölümleri: Giriş, Donanım listesi, Yazılım akış şeması, Kurulum, Sonuç, Kaynakça. README’de pin tablosu ve kütüphane sürümleri yazın.
